# Composer

把「悲伤」「要强烈」「像某首歌」这类抽象想法，变成**能立刻听见、能看见、也能自己验证**的编曲草稿。

---

## 0. 这份文档是什么

这是一份**项目宪章**，不是 API 文档，也不是路线图。

它记录的是：我们相信什么（哲学）、被什么约束（硬约束）、已经排除了什么（判断）、还不知道什么（开放问题）。

> **现状：本仓库目前没有代码。**
> 前一版（MuseScore QML 插件 + 乐队 MSCX 模板）已被删除，知识沉淀在第 11 节，原始文件在 git 历史 `b0487de`。
> 在核心表示层定型之前，不写产品代码。

## 1. 问题

### 1.1 表面问题 vs 真实问题

表面的说法是：*不想在 MuseScore 里一个音符一个音符点鼠标。*

但那只是症状。真实的困难是：

> **从「脑子里的感觉」到「听到的声音」之间，有一条不可观测、不可验证的鸿沟。**

你心里清楚"这段要压着，副歌才炸"，但这个判断在变成声音之前无法被检验，而且你自己也说不清它由哪些参数构成。

### 1.2 为什么"让 AI 直接吐音符"会失败

这条路我们已经走过一遍，失败原因很具体，不是模型不够强：

| 失败 | 表现 | 根因 |
|------|------|------|
| **不可收敛** | "再悲伤一点" → 整体重写 → 开盲盒 | 没有参数，就没有微调；只有重新抽样 |
| **不可解释** | "有点怪，但说不出哪怪" | 无法归因到密度/音区/张力/动态中的哪一项 |
| **不可验证** | 对不对只能靠反复听 | 意图的后果没有被测量 |
| **迭代太慢** | 改一次要开 GUI、等加载 | 重工具进入了开发循环 |
| **不可积累** | 好版本留在聊天记录里，下次重来 | 成果不是仓库里的资产 |

### 1.3 于是，我们要做的是什么

不是"AI 生成音乐"，而是：

> **可收敛的迭代。** 每一次修改都更接近意图，且不会摧毁上一轮喜欢的东西。

"收敛"是本项目唯一的核心指标。任何设计选择都用它来审判。

## 2. 第一原则

**P1｜表示层才是产品。**
AI 生成音符不值钱。值钱的是那个中间表示：既能让语言落到参数上，又能确定性渲染成声音与乐谱。工具（MuseScore / Guitar Pro / 任何 DAW）都只是出口。

**P2｜收敛 > 生成。**
宁可生成能力平庸但"参数可调、改动可预测"，也不要一次惊艳但无法复现。可复现性优先于表现力上限。

**P3｜模糊意图必须可分解为可度量的音乐后果。**
"悲伤"不是音符，是一组跨声部的参数（调式、和声节奏、密度、音区、留白、动态、音色）。这张分解表是项目的真正资产——不是 prompt，不是 API。

**P4｜反馈必须可测量。**
人耳判断"像不像"之前，系统要能先说出"这里密度 0.7、三件乐器挤在 C3、长号这句没有换气口"。**可演奏性 lint 是音乐世界的编译器报错**——有了它，AI 才可能自己纠正。

**P5｜听见 + 看见 是产品界面，乐谱不是。**
用户用耳朵和眼睛确认想法。乐谱、分谱、打印都发生在验证之后，属于外环。

**P6｜时间预算决定架构。**
内环（改→听）必须 ≤ 2 秒且完全离线；外环（打磨/打印/给乐队）可以是分钟级人工操作。**任何重型 GUI 软件进入内环，都是架构错误。**

**P7｜资产，不是对话。**
编曲必须作为可 diff、可复现、可分享的文件活在仓库里，"上次那版不错"不能只存在于聊天记录。

**P8｜诚实抽象。**
不确定的事绝不假装确定。不返回假的 success，不提供"看得见但没生效"的操作，不用"看起来对"掩盖语义漂移。**歪掉的成功比明确的失败昂贵得多。**

**P9｜现实的人。**
乐队编制是固定的七件真乐器，有呼吸、有指法、有把位、有体力。可演奏性是硬约束，也是通用 AI 音乐工具给不了我们的差异点。

**P10｜人是最终裁决者。**
系统的任何输出都只是**候选**。"够不够悲伤""能不能演"这个判断不可外包，不可优化，不可代理。由此推出的不是"保守"，而是相反：**模型可以大胆到不讲道理，只要判断足够便宜**。所以我们绝不用"怕平庸"作为收窄搜索空间的理由；我们只花力气在**让人能快速比较和否决**上。

**P11｜编制是调色板，不是清单。**
七件乐器是颜料，不是必须出现的颜色。**某个声部不出现，是合法的、而且经常是最强的手段。** 不要为了"完整性"把编制填满——填满只会吵。

**P12｜空与未决是一等值。**
`absent`（这件乐器这里不响）和 `undecided`（这里我给不出想法）都必须能写下来、显示出来、被保留。系统**不得为了完整而自动填补**，也不得把"没想法"渲染成默认值。
允许编不出来：这个项目本来是"验证一个 idea 行不行"，那么"不行 / 不知道"当然是合法答案。

**P13｜没有必须主导的那一个。**
不允许任何乐器或人声被声明为"整曲的主导"。那是**先验指派**，而我们相信的是听感与交织的产物。

- "谁被听见"**不是输入，是测量**：每小节每个声部的显著度（音区是否独立、是否唯一在动、密度、动态占比）算出来，随时在变。
- 编排的对象不是声部，是**声部之间的关系**：对答、接力、互补、叠置、让位、影子、碰撞。化学反应发生在那里。
- 关系层**只测量、只描述，不禁止**——"齐奏"与"糊"在很多数字上长得一样，只有耳朵能分开（P10）。

> 人声的特殊性不在"主导"，而在**携带语言**：有词人声与别的声部撞了，语言会被吃掉，那是硬约束。
> 但"有词人声必然优先"同样是流行音乐的默认假设，不是原则。

**P14｜输入是骨架，不是成品。**
一首歌、一段动机、一条和声进行，都只是**骨架**——可识别的最低要求。
骨架之上应当能长出更丰满的东西，包括**离题**与**拼接**。
判断离题成立与否的不是"好不好听"（P10），而是两个可测的量：**离了多远**、**有没有回来**。

## 3. 音乐模型

这一节回答的不是"用什么格式存音符"，而是**我们到底认为音乐是什么**。因为后面的所有表示、生成器、分析指标，都只是这个模型的具体化。

### 3.1 一句话

> 一首曲子 ≈ **在状态空间里的一条轨迹**，由**意图参数化的政策**驱动，最后**织成音符**。

### 3.2 两个来源，一个合成

**来源一：音乐是时间的函数。**（Tidal/Strudel、FRP、Xenakis 的随机音乐）
`piece : Time → Event*`

- 得到：**可采样**（任意 t 求值 → 段落循环、A/B、跳到第 17 小节、离线导出）、**参数自动化免费**（任何参数都能是时间的函数，情绪曲线成为一等公民）、**组合性**（函数复合 = 音乐叠加；拉伸/移位/倒影 = 算子）。
- 缺陷：纯时间函数是**预先写死**的，它无法表达"这个动机，移到当前和弦上"——因为"当前和弦"不是它的自变量。

**来源二：音乐是在和弦空间里的游历。**（Tonnetz / 新黎曼理论 / Tymoczko 的几何 / Xenakis 的 *outside-time*）

- 得到：声部进行变成"求最近邻"；**转调的代价可计算**；大尺度形式与小尺度和声统一；**情绪 = 期待的建立与兑现**（Huron）——而"游历"字面上就是一个期待模型。
- 缺陷：它只回答和声，对鼓、音色、节奏密度一言不发。

**合成：柯里化。**

```
F : (Time, HarmonicState, AffectState) → Event*
```

- **L1 规格** = `F` 的参数 + `HarmonicState` 的语法 + `AffectState` 的取值
- **L2 事件图** = 把后两个自变量固定后，`F` 退化为纯时间函数，求值即得

这一步在数学上很轻，但设计上很重：**"写死的音符"与"随上下文变形的音符"在同一个模型里共存**——前者是常数函数，后者是依赖 H 的函数。

> **记谱语言是值域（codomain），不是载体（carrier）。**
> MusicXML / LilyPond / ABC 记录的是 *what*（哪个音、多长、怎么连），天生丢掉 *why*。
> 所以：**别在记谱语法上设计任何东西**，只在最后一步做无损编码。

### 3.3 四个层

```
   意图 A(t) ──► 政策 Policy        怎么走：多快、多远、哪里停、要不要跳
                       │
   规格 S ────► 空间 Space          哪些状态可达：和声/音阶/节奏/音区/织体的语法
                       │
                       ▼
                轨迹 Trajectory      γ : [0,T] → Space   —— 具体的游历
                       │
                织物 Texture         每件乐器此刻做什么（角色生成器）
                       │
                       ▼
                   L2 事件图
```

| 层 | 是什么 | 谁决定 | 数据形态 |
|---|---|---|---|
| **政策 Policy** | 情绪的落点。**怎么走**的策略 | affect 词表 + 人 | 一组参数（跳/邻、快/缓、延迟/即时解决） |
| **空间 Space** | 音乐的语法。什么状态合法 | 调式/和弦字典/节奏文法 | 图/格 + 约束 |
| **轨迹 Trajectory** | 实际游历的路径 | 政策驱动，人可 pin | 有序的状态序列（含时间） |
| **织物 Texture** | 音符级实现 | 角色生成器 | 音符事件（唯一需要"音符字符串"的地方） |

**关键推论：之前关于"YAML 还是 Strudel"的争论，落在了错的层。** 音符文本只负责最内一层的织物；政策、空间、轨迹根本不该用音符文本表达。所以那个选型问题的严重性大幅下降。

### 3.4 形式 = 同一概念的不同时间尺度

- 大尺度：段落的安排 = 路径形状（离开家 → 到远方 → 回来）
- 小尺度：和声进行 = 同一件事
- "副歌要炸" = 抵达一个远处然后解决；"主歌压抑" = 在原地徘徊、不远走

**形式与和声不是两个系统，是同一个路径概念在不同时间尺度上的投影。** 这让"结构"第一次不需要单独一套机制。

### 3.5 情绪词表因此有了正确的结构

不再是"悲伤 → 小调"这种符号对照，而是三列：

| 词 | 空间偏好（Space） | 路径形状（Trajectory） | 织物（Texture） |
|---|---|---|---|
| 悲伤 | 小调/自然音，低位音区，宽间距 | 邻接缓行，少跳跃，**延迟解决** | 稀疏、持续音、大量留白 |
| 强烈 | 高张力区（属七/减三和弦），宽音域 | 频繁跳转，短促解决，**一次大跳** | 密集、齐奏、动态顶格 |
| 克制 | 窄音域，同区和弦 | 反复徘徊，不离家 | 少乐器、弱动态、闷音 |
| 期待 | 离家 | 长悬置，最后一脚落地 | 渐强，鼓加密 |

每一项在生成器里都有对应实现——这才叫"可分解为可度量的音乐后果"（P3）。

两处修正（来自 spike 0）：

1. **实际填写顺序是 织物 → 空间 → 路径**，与列序相反。词越抽象（"恢宏"），织物占的比重越大。
2. **但这个比重是词条级 / 段落级变量，不是定律**（见 C11）。同一句话在不同段落可以有完全不同的倾斜。

### 3.6 分析层因此第一次可计算

| 指标 | 由什么导出 |
|---|---|
| 张力曲线 | 状态与"家"的距离 + 路径导数 + 不协和度 |
| "走远了没有 / 有没有回家" | 路径的位移与回归 |
| 声部进行是否平滑 | 和弦空间中的距离（Tymoczko） |
| 形式是否成立 | 路径形状在多个时间尺度上是否自相似 |
| 等音拼写（G# 还是 Ab） | 在和弦空间里选最近的表示 —— 纯 MIDI 层没有这个信息，这正是"事件图→乐谱"最烦的坑之一 |

这把我原先列的"和声张力"从手调参数变成了**由理论导出的量**，P4 第一次有了真正可实现的内容。

### 3.7 空间的轴（至少四条）

原先这一节只有一个轴（和声），这是模型最大的缺口：**"进行曲"和"恢宏"有一半写不出来**，因为它们根本不是和声概念。

| 轴 | 内容 | 可用理论 | 状态 |
|---|---|---|---|
| **和声** | 功能、借用、转调 | Tonnetz / 新黎曼 / Tymoczko | 成熟 |
| **节奏 / 节拍** | 律动、重音、错位、欧氏 | Krebs 的节拍错位理论 | 成熟 |
| **音区 / 织体** | 密度、音区占用、留白 | 基本空白 | 待自建 |
| **在场 presence** | 谁在响、谁不在 | 无既有理论 | **新，见下** |

#### 在场空间

> **配器 = 在「7 件乐器的幂集」（2⁷ 个状态）里走的一条路径。**

- **空集是合法状态。** 静默不是"没有设计"，它是空间里的一个点。
- "不出现"与"出现"是同一机制的两种取值，不是两套机制。
- 于是"恢宏"可以写成 **"从 1 件到 3 件用了 8 小节，再一次性到 7 件"**，而不是 `density: 0.8`。
- **连续密度旋钮的形状是错的**：它假设"大家都在、只是弹得稀"，而真相是**"谁不在"才是主武器**。

实证来源：贝多芬第九末乐章。《欢乐颂》的主题**第一次出现是裸的、轻的、单声部的**，全场力量来自随后逐层加厚，而不是一开始就满。

### 3.8 这个模型的边界（诚实地说）

- 和声这一轴只管**和声与结构**；鼓、音色、密度要另三条轴（3.7）。
- **最短路径 = 最平庸的音乐。** 声部进行最平滑的解恰恰是"对但无聊"。所以距离必须是被 affect 控制的**参数**，而不是被最小化的目标——"强烈"就是允许大跳。
- 三元和声的文化局限：四度叠置、音簇、调式混合，新黎曼理论都很勉强。
- **形式化 ≠ 动人。** Xenakis 的形式化音乐听起来像 Xenakis，不像"悲伤"。这个模型保证的是**连贯**，不是**感染**。

> 最后一条不是要规避的风险，而是**已接受的代价**。理由见 P10：模型可以大胆，判断必须便宜。
> 因此本项目的力气会更多地花在 **A/B 对比、边界量化热替换、多候选** 上，而不是花在"如何让算法不写平庸的东西"上——后者是伪问题，前者是工程。

### 3.9 参考谱系（我们站在谁肩上）

| 谱系 | 给我们的 |
|---|---|
| **Xenakis**：*outside-time* / *in-time* | L1 / L2 之分。1963 年就说清了 |
| **Tonnetz / 新黎曼理论**（Cohn, Fiore） | 和弦是格点，P/L/R 是移动；转调 = 走位 |
| **Tymoczko《A Geometry of Music》** | 和弦空间 = 有序音高元组的商空间；**距离 = 声部进行的平滑度** |
| **Huron**：期待理论 | 情绪 = 预测的建立、违反与解决 → "游历"为何能承载情绪 |
| **Tidal / Strudel** | 时间函数 + 可采样 + 参数自动化（**作投影，不作真源**） |
| **Sorensen / Extempore**（The Concert Programmer） | 代码即数据 → 免费的可寻址性；**变更落在下一个音乐边界**；单声部热替换不中断时间基 |
| **算法作曲传统**：Common Music / OpenMusic / Slippery Chicken | "结构化音乐描述 → 生成 → 乐谱"这条管线，比 live coding 更贴我们的问题 |
| **Abjad** | 出口层首选试验对象：Python 里精确控制连音线/符杠/嵌套 tuplet，输出 LilyPond |

### 3.10 人声：文本、角色、约束

四层装得下"人声这件乐器"，**装不下它的文本，也装不下它迫使编曲回答的那个问题——"这段让谁被听见"。**

#### 先拆开三件被混在一起的事

| | 是什么 | 当前模型有吗 |
|---|---|---|
| **作为乐器** | 单音、受呼吸限制、有个人音区，**还有换声区（passaggio）** | 部分（乐器类型可扩） |
| **作为文本** | 字-音绑定、咬字、句读停顿。**唯一携带语言的声部** | ❌ 完全没有 |
| **作为叙事** | 谁在唱、唱给谁、哪一句是"点"。它决定整份编曲的走向 | ❌ 完全没有 |

三个自变量，**不要揉在一起**：

| 自变量 | 取值 | 决定什么 |
|---|---|---|
| **是否携带语言** | `text: true/false` | 约束的重量（咬字、遮蔽、换气） |
| **是否有人声** | 乐器种类 | 音色与演奏法 |
| ~~谁主导~~ | —— | **不是变量，是测量结果**（P13） |

于是"人声"不是一个开关，而是四种合法形态：

| | **它在听感上突出** | **它退在后面** |
|---|---|---|
| **有词** | 流行歌（默认假设） | 伴唱 / 和声 / 念白 / 器乐曲中的人声插段 |
| **无词** | 阿卡贝拉化 hook、哼鸣主题 | 氛围层（ooh/aah）、器乐作品里的音色层 |

四种都要能写得出。**写不出哪一种，模型就是错的。**
注意左列和右列不是靠 `primary:` 字段指定的，而是靠**写完之后的听感（以及测量）**。

#### 显著度是测量，不是声明

没有 `primary:` 这个字段。取而代之的是一个**每小节的显著度剖面**，由事件流算出来：

| 特征 | 含义 |
|---|---|
| 音区独立性 | 与其余声部的音区重叠越小，越容易被分辨 |
| 运动独占 | 别人都停着而它在动（或反之）——最强的注意力拉手 |
| 事件密度 | 本小节音符数相对其他声部 |
| 动态占比 | 它在总响度中的份额 |
| 进入时机 | 单独进入、或在休止后第一个进场 |

这些是**描述**，不是禁止。它们告诉人"此刻实际听到的是谁"，而不是规定"应该听谁"。

#### 模型补充（四条）

1. **voice 乐器类型**：`range` / `comfort` / **`passaggio`** / `text: true` / `breath: strict` / `stamina`。
   换声区是人声独有的——长时间停在那里是真实的演唱危险，而其他乐器没有这个概念。
2. **词层**：每小节的 `degrees` 旁边挂一行 `text`，**一一对应**，破折号表示一字多音。
   这本来就是中文乐手写简谱的方式，不是新语法。
3. **关系层**（见 3.11）：编排的对象是"对"，不是声部。
4. **叙事计划 `vocal_plan`**：谁在唱、唱什么状态（solo / 三度和声 / 同度齐唱 / 无伴奏 / 无词）。
   **和声人声不是独立写的**：从 lead + 和弦派生（取上方最近的弦内音，且间隔 ≥ 三度）。

#### 新的 lint 类别（区分条件，不一律上刑）

| 检查 | 什么条件下适用 |
|---|---|
| **遮蔽 masking** | 有词人声参与的**那一对**：对方同时占着它的音区 + 节奏，字会被吃掉 |
| **呼吸 breath** | 所有受呼吸限制的声部；两个管乐声部不应互相堵住气口 |
| **咬字 diction** | 有词人声：每拍音节数 vs tempo；抱腔落在辅音重的字上 |
| **换声区** | 有词/无词人声都适用（生理限制） |
| **和声正确性** | 和声声部 vs 和弦：音程是否协和 |

#### 歌词决定走向（不是装饰）

- 行的**语义重量** → 全员在哪里落、在哪里拆
- **音节密度** → 乐句长度 → 和声多久必须换
- **一字多音**的位置 → 往往是情绪顶点

> 这意味着 `vocal_plan` 不是 L1 的一个字段，它是 **L0 的一部分**：它和"悲伤 / 像某首歌"是同一类东西——都是把人脑里的东西对齐到系统能处理的概念上。

### 3.11 关系层：编排的对象是"对"，不是声部

四层（政策 / 空间 / 轨迹 / 织物）都是**关于单个声部**的。但"化学反应"发生在两个声部之间——那里目前什么都没有。

#### 关系的类型（都要能写出来）

| 关系 | 描述 | 在本曲里的位置 |
|---|---|---|
| **对答** | A 动 → B 动，交替 | 长号与吉他 |
| **接力** | 同一动机换手 | 小提 → 长号 → 吉他 |
| **互补 / 交错** | 两者都不完整，合起来才成形 | 贝斯与底鼓 |
| **叠置** | 有意同度 / 八度 | 第 17–22 小节的全员段 |
| **影子** | 错开半拍到一拍的同一条线 | 主音吉他 vs 小提 |
| **让位** | 一个退场，另一个浮现 | 第 23 小节 |
| **碰撞** | 同节奏 + 同音区 + 同动态 | 要提示的 |

#### 可测的指标（每对）

| 指标 | 怎么算 |
|---|---|
| 节奏重合 | A 的起音点上，B 也在起的比例 |
| **交错度** | `(|A∪B| / 网格) × (1 − 重合)` —— 这才是"交织"的可测形式 |
| 音程中位数 | 同时发声时两者音程的中位数 |
| 同度 / 八度率 | 同时发声且相差 0 或 ±12 的比例 |
| 音区重叠 | 两者实际用到的音区交集 |
| 轮廓关系 | 同向 / 反向 / 斜向 |

#### 唯一的硬规则

**只有一条：有词人声参与的碰撞是硬约束。** 其余全部是描述。

> 这是全项目唯一保留"硬"的地方，而且理由不是审美，是**信息**：字被盖住，语义就没了。
> 除此之外，模型不对音乐下命令——它只说"现在听起来是这样"，然后由耳朵决定好不好（P10）。

### 3.12 骨架与离题：忠实度是一条可测的曲线

目前的 spec 把两件不同性质的东西揉在同一层：**送别的旋律** 和 **"第 17 小节谁进来"**。
前者是**源**，后者是**演绎**。不分开，"从骨架长出来"在数据上就没有位置（见 `CAPABILITY.md` D1）。

#### 四档忠实度

| 档 | 定义 | 判据 |
|---|---|---|
| **骨架 skeleton** | 源材料本体，可识别的最低要求 | 旋律音 / 词 / 和声骨架 |
| **派生 derived** | 由骨架经**可指认的变换**得到 | 能说出"这是第 3 小节的倒影" |
| **离题 digression** | 不可追溯，但与骨架形成张力 | 距离可测 + 是否归还 |
| **外料 foreign** | 引自他处 | 显式引用 |

#### 一个机制，两种结果

```
   离骨架距离
0 ────────────────────────► 时间
   骨架 ── 派生 ── 离题 ╱╲  归还
                        ╲__  ← 归还 = 发展部
                             ← 不归还 = 拼接
```

**离题 + 归还 = 发展部；离题 + 不归还 = 拼接。**
两者共用同一个机制，只由"是否归还"区分。这接上了之前那条：**终点距离 ≠ 0 = 出发**。

拼接真正要设计的是**接缝**：共同音 / 节奏枢轴 / 持续音 / 静默 / 过门遮蓋 / 强行硬切。

#### 可测的：fidelity 曲线

每小节一个 0–1 的值，由四项合成：旋律重合率、动机重现、和声距离、织体连续性。

> 它直接回答：**离了多远、有没有回来、回来的时候还认不认得出。**
> 没有它，"离题"就只能靠形容词。这是 C1–C4 四个缺口的公共前置。

## 4. 架构形状（暂定，未锁定）

```
      「悲伤」「像《Creep》」「副歌进长号」
                    │
         ┌──────────▼───────────┐
         │ L0  意图层            │  人类语言 / 情绪词 / 参考曲
         │     + 情绪词表(lexicon)│  → 归一化为 政策 + 空间选择
         └──────────┬───────────┘
                    │  LLM 只在这一层工作
         ┌──────────▼───────────┐
         │ L1  编曲规格 Spec     │  ★ 唯一可编辑真源
         │  空间 + 政策 + 轨迹约束│  树形、可寻址、可 diff、可回滚
         │  + pins + seed        │  （音符文本只属于最内层的织物）
         └──────────┬───────────┘
                    │  确定性生成器 + 演奏法约束
         ┌──────────▼───────────┐
         │ L2  事件图 NoteEvents │  构建产物（可被 pin 覆盖）
         └──┬────────┬────────┬──┘
            │        │        │
         音频渲染  可视化  分析与 lint
         (内环)   (钢琴卷帘) (距离/张力/密度/音区/可演奏性)
            │
            └──────► 出口：MusicXML / MIDI ──► MuseScore / Guitar Pro / DAW
```

### 三层权威（这条决定成败）

内容从哪来，优先级固定为：

1. **Pinned（人钉住的）** —— 用户自己弹或指定的音符或路径点，**永远赢**，生成器不得覆盖。
2. **Generated（生成的）** —— 由「政策 + 空间 + 角色 + seed」确定性生成，占绝大多数。
3. **Inferred（推断的）** —— 从 affect 向量推出的默认值，可被上面两层覆盖。

> 如果一条设计让人无法"钉住某个乐句"，它就是错的。乐手一定会说"这句我要这么唱，你别动"。

### 双环

- **内环**：改参数 → 重生成 → 合成 → 听 / 看 / 测量。秒级，无 GUI，可 headless（agent、CLI），也可在浏览器里跑。
- **外环**：导出 MusicXML → MuseScore / Guitar Pro 精修、排版、打印、发给乐队。

## 5. 硬约束

**C1｜编制是输入，不是常量。**
代码里不允许出现"七个人"。谁在场、每件乐器的绝对音域、舒适区、惯用音型、是否单音——全部来自
`ensembles/*.yaml` + `instruments/*.yaml`。加人、减人、换乐器**不改代码**。

- 该做深的地方是**对真乐器的刻画**（idiom、换气、指法、双音、把位），而不是"支持任意编制"的空泛通用性。
- **音区分三层：**

| 层 | 含义 | 越界后果 |
|---|---|---|
| `range` 绝对可演奏 | 物理上能不能奏出来 | **错误**：必须修 |
| `comfort` 舒适区（推荐） | 这个音区里它才好听、才能持久 | **提示**：可接受，但要知道 |
| 人为覆盖 | 座位上的 `overrides` | 优先于推荐值 |

> “推荐”是系统给的，最终是演奏者说了算（P10）。同一个乐器，不同乐手舒适区不同——
> 这就是为什么它必须是**座位**的属性，不是乐器类型的绝对真理。

乐器的具体定义在 `instruments/`（现已包含 violin / trombone / electric-bass /
acoustic-guitar / electric-guitar / ewi / piano / drum-kit），编制在 `ensembles/band.yaml`。

**C2｜内环不依赖任何重型 GUI 软件。** MuseScore / Guitar Pro / DAW 只能出现在出口。

**C3｜确定性可复现。** 同一份 Spec + 同一 seed → 逐事件相同。允许随机，但随机必须被 seed 固定并可重放。

**C4｜修改是结构补丁，不是文本重写。**
Spec 必须是**有稳定路径的树**；一次修改 = 「路径 + 新值」（JSON-Patch 语义），可校验、可语义 diff、可回滚。"贝斯太密了"必须落成一次局部补丁，而不是让谁重写整份东西。
这直接决定了哪些表示方案可用：**只能被文本重写的东西（如代码）不适合当真源。**

**C5｜人类干预优先。** 见"三层权威"。手改结果不可被下一次生成默默吞掉。

**C6｜双环境可跑。** headless（CLI / agent）与浏览器都要能驱动同一条管线，不允许只有一边能工作。

**C7｜出口用通用格式。** MusicXML 优先（MuseScore、Guitar Pro 7+、Dorico 等都能进），MIDI 用于试听与 DAW。**不为任何单一软件写专用适配器**，除非它有明确不可替代的价值。

**C8｜说用户的词。** 中文情绪词、参考曲名、简谱式数字音级（`1 2 3 5`、`0` 为休止）。让输入接近他脑子里已有的东西，而不是接近机器。

**C9｜改动量化到音乐边界。**
所有变更在下一个拍或小节边界生效，绝不在乐句中间炸开；内环的**时间基永不中断**，声部可热替换（鼓在跑，只换贝斯）。
否则听感上根本无法判断改动的效果，A/B 就无从谈起。

**C10｜让判断变便宜。**（P10 的工程化）
A/B 对比、段落循环、单声部 solo、多候选并排，属于**核心基础设施**，不是附加功能。系统的产出越冒险，这一条越重要。

**C11｜不存在全局权重常数。**
任何"哪一层更重要"（空间 / 轨迹 / 织物 / 分析）都是**词条级或段落级的变量**，不得写进模型当作定律。一次观察不是规律。

**C12｜全员段是齐奏，不是七个声部。**
七件乐器同时各说各话只会吵。厚重感来自**同音与八度叠置 + 低频相位一致**，不来自声部数量。lint 应检查：全员段里有没有同音/八度加倍？没有就提示"声部多但不厚"。

**C13｜约束挂在"对"上，不挂在层级上。**
不设全局焦点，也不设"人声优先"。所有判断都是**成对**的：

- 两个声部同时**同节奏 + 同音区 + 同动态** → **碰撞**：提示，不是错误。
- **有词人声参与的碰撞 → 硬约束**（语义会被吃掉）。这是全项目唯一保留的硬规则。
- **无词人声**就是一件音色特殊的乐器，没有特权。
- "谁让谁"不由模型决定，由编排意图决定；模型只**报告**让位与交接发生在哪里。

## 6. 明确不做的事

- ❌ **不做通用 MuseScore SDK**，不做 MCP 工具集堆叠。插件、协议都不是产品。
- ❌ **不做 live coding 玩具**。我们优化"迭代一个作品"，不是"当场表演一段"。
- ❌ **不做打谱器 / 记谱编辑器**。排版交给 MuseScore。
- ❌ **不做"AI 一键生成完整成品"**。我们是草稿验证器；人保留判断权。
- ❌ **暂不做音频转录**（哼唱/录音 → 音符）。远期诱人，现在会把项目重心带偏。
- ❌ **不为了通用性牺牲可寻址性**。能用但无法精确修改的方案，一律不采。
- ❌ **不发明语言**。见第 7 节。
- ❌ **不用"怕平庸"收窄搜索空间**。见 P10 / C10。

## 7. 表示层：候选项与诚实评估（**未决，但已降级**）

> **注意：第 3 节之前，这一节是"当前唯一真正卡住的问题"。现在不是了。**
> 空间/轨迹/政策都必须用结构化数据表达，"音符怎么写成文本"只决定最内层织物的写法。
> 因此下面讨论的是**织物层语法 + 真源形状**，不再是整个项目的根基。

### 7.1 判断标准

| 标准 | 说明 |
|------|------|
| 可寻址 | 能否对"贝斯密度"这种子概念做最小补丁 |
| 表达力 | 节奏/音型的写法是否够密、够自然（尤其 euclid、隔段变化、动机变形） |
| 可 diff | 两次修改能否语义化对比 |
| 记谱出口 | 到 MusicXML 的成本 |
| 可 pin | 能否钉住某个乐句并让它免疫生成 |
| LLM 友好 | 出错是响亮的（报错）还是沉默的（合法但错） |
| 可自造 | 是自己造语法，还是复用既有语法 |

### 7.2 候选

| 候选 | 强 | 弱 |
|------|----|----|
| **A. 纯数据（平铺音符列表）** | diff 干净、易于 lint | 节奏表达极啰嗦；写《送别》副歌会让人烦躁 |
| **A′. 树形 Spec + 结构补丁**（A 的修正版） | 稳定路径 → C4 成立；混合层（空间/政策/轨迹/织物）天然适配；空层可省 | 需要设计路径语义（不能是随意嵌套） |
| **B. A′ + 内嵌 mini-notation 字符串** | 兼得：参数可寻址 + 节奏表达力；数字音级 ≈ 简谱 | 两套心智（数据 + 字符串）；mini-notation 无小节/时值语义 |
| **C. Strudel / Tidal 代码作为真源** | 节奏与变换算子最强；参数自动化原生；pianoroll/试听白送 | **无寻址** → 改参数 = 让 LLM 重写 JS（沉默出错的温床）；pin 很别扭；**记谱出口是负分**；违反 C4 |
| **D. ABC / LilyPond 作为真源** | 记谱出口极好 | 本质是排版语言（值域当载体用，见 3.2）；迭代与节奏变换很痛苦 |
| **E. music21 / partitura / Abjad 对象** | 出口层成熟（Abjad 排版语义最强） | 作为**真源**太重、无模式代数 |
| **F. MIDI + 旁注** | 通用 | 表达能力最低，无意图、无结构，等于放弃抽象 |

### 7.3 当前倾向（**假设，不是结论**）

**B 为主真源 + C 作一次性投影。**

- 真源 = 树形 Spec（YAML/JSON），外层是空间/政策/轨迹，内层织物的节奏字段吃 mini-notation（复用它成熟的解析器，不自己造语法）；音高优先用数字音级。
- 试听层 = Strudel（浏览器里跑，白拿声音与 pianoroll）。**它是可丢弃的构建产物，用户和 LLM 都不手改它**——这样它的短板全都落在最外层。
- 记谱出口 = 从自己的事件图导出 MusicXML；先试 **Abjad**（排版语义），music21/partitura 作备选。

理由一句话：**Strudel 优化的是"当场表演"，我们优化的是"可收敛地迭代一个作品"。** 前者可以借用，后者不能替换。

### 7.4 但先别信这个倾向

见第 10 节。**这个问题必须由实验判定，不由论证判定。**

| Q6 | **四条轴各自的语法从哪来**（和声 / 节奏 / 音区织体 / 在场） | 模型原先只有和声一条腿，"进行曲""恢宏"因此写不出来 | 和声与节奏有现成理论；音区织体与在场需自建，先做最小可用 |
| Q7 | 手改回读（在 MuseScore 改完怎么并回来） | 不解决则外环成果会丢 | 先做单向 + locked 区；回读明确延期 |
| Q8 | 测量与感知的偏差（数字对、听着不对） | 会让"可验证"变成假象 | 测量的每一项都必须有过一次"数字→耳朵"的校准 |
| Q9 | 简谱是否应作为一等输入 | 中文乐手的默认心算方式 | 在 spike 里直接用数字音级写，看是否顺手 |
| Q10 | 音源保真度 | GM 音色差会影响判断 | 先用 GM 做草稿，外环再换真音色 |

## 9. 风险

- **R1｜自造语言的陷阱。** 设计 DSL 会吞掉几个月，而语法是最不值钱的部分。缓解：不造语法，只定数据形状（7.3）。
- **R2｜情绪词表的空转。** "悲伤"跨文化、跨人差异大。缓解：词表条目必须可试听验证，否则删除；三列结构强制每一条都落到可实现的东西上。
- **R3｜过度工程。** 在内环能听见之前铺开 lint、词表、回读、可视化，会原地踏步。缓解：Milestone 顺序锁死，只许往前。
- **R4｜工具幻觉。** MuseScore 的既有坑（状态漂移、静默失败）已经证明"把工具塞进循环"会消耗全部预算。缓解：C2。
- **R5｜元层漂移。** 花在讨论架构上的时间超过做实验的时间。缓解：任何争论超过一天，立刻转成 spike。
- **R6｜几何的诱惑。** 路径/距离/张力这些概念太漂亮，容易让人把"结构自洽"误当作"作品成立"。缓解：P10 —— 唯一验收标准是人的耳朵，不是模型的美感。

## 10. 判定方式：三个 spike

不辩论，做实验。每个 2–3 小时，用同一段音乐（《送别》副歌）作对照。

1. **表达力**：用 A（纯数据）和 B（内嵌 mini-notation）各写一遍。**我写得下去吗？** 写不下去的方案直接淘汰。
2. **可寻址 + 可听**：模拟"贝斯太密了"，看补丁长什么样、是否可信、能否在**小节边界**热替换而不中断播放。
3. **记谱出口**：从事件图导出 MusicXML（Abjad 优先）→ MuseScore 打开 → **连音线、符杠、鼓谱、等音拼写是不是人样？** 这是最痛也最未验证的一环。

**新增 spike 0（最便宜，建议先做）**：用「空间 + 轨迹」的语言（不是音符）把《送别》副歌**手写描述**一遍——写成"从主走向属、两次延迟、最后落在下属"这种。如果人写不出/写不出有用的东西，说明第 3 节的模型对该用户不成立，要立刻回来改模型。**这一步不需要任何代码。**

判据：全部通过 → 进入 M0；任一失败 → 换候选重跑。

## 11. 从前一版继承的经验（不要重犯）

已删除的 QML 插件曾把管线跑通过，也暴露了一组具体教训。它们不是实现细节，而是**关于"把编排系统架在别人的 GUI 上"的结构性结论**：

- **只读操作不要包进 undo 事务。** 读一次乐谱压一条空 undo，"undo 有上限"的抱怨多半来自这里。
- **别把状态放在插件的全局变量里。** 依赖"用户此刻在软件里选中了什么"的 API，一旦用户点了鼠标就错位。需要的是**按地址写入**（staff + 起始 tick + 音符序列），无状态、幂等。
- **批量执行必须传播错误。** 序列里第 7 步失败后继续写，会产出"散落在奇怪位置"的音符。
- **不要提供会说谎的接口。** 有个命令"校验参数 → 打开对话框 → 返回 success"，还有个"静音"其实是隐藏（视觉消失、声音还在）。歪掉的成功比明确的失败贵得多。
- **动态加乐器后 staff 索引不可预测**，于是被迫用固定模板 — 这是"用静态文件补 API 缺陷"的典型症状。
- **音色/发声问题在一个 GUI 里排查成本极高**（当时的现象：只有鼓出声，原因至今未确认）。这类不确定性不该出现在内环。
- **"清空后全量重写"是错误的迭代模型。** 它曾被视为唯一手段，代价是每次迭代都失去时间连续性与可比性 —— 于是你永远不知道"这次改动到底改善了什么"。

结论：**工具可以是出口，但不能是地基。**

## 12. 词汇表

| 词 | 含义 |
|----|------|
| **意图层 L0** | 人类语言、情绪、参考曲。易变、不精确、不是资产。 |
| **规格 Spec L1** | 可寻址的编曲描述（空间 + 政策 + 轨迹约束 + pins + seed），唯一可编辑真源。仓库资产。 |
| **事件图 L2** | `(声部, 起止时间, 音高, 力度, 发音法)` 的平坦列表。构建产物。 |
| **政策 Policy** | **怎么走**：跳/邻、快/缓、延迟/即时解决。情绪的工程化落点。 |
| **空间 Space** | **哪些状态可达**：和声/音阶/节奏/音区/织体的语法。可分析、可约束。 |
| **轨迹 Trajectory** | `γ : [0,T] → Space`，具体的游历。L2 的骨架。 |
| **织物 Texture** | 每件乐器在此刻做什么。唯一需要"音符字符串"的层。 |
| **outside-time / in-time** | Xenakis 之分：前者是结构与语法（≈ L1），后者是时间中的实现（≈ L2）。 |
| **角色 Role** | 跨乐器的功能抽象：lead / counter / pad / comp / arp / root / drive / rhythm。 |
| **在场空间** | 7 件乐器的幂集（2⁷）。配器 = 在这里走的一条路径；空集合法 |
| **显著度 salience** | 每小节每个声部"被听见"的程度。**测量出来的，不是声明的**（P13） |
| **携带语言 text** | 人声是否载词。它单独决定约束的重量，与是否突出无关 |
| **关系 relation** | 两个声部之间的形态：对答 / 接力 / 互补 / 叠置 / 影子 / 让位 / 碰撞 |
| **交错度 interlock** | |A∪B| 高而 |A∩B| 低 —— "交织"的可测形式 |
| **骨架 skeleton** | 源材料本体（旋律/词/和声骨架）。缺了它就不叫这首曲子 |
| **离题 digression** | 不再可追溯到骨架的那一段。成立的条件是距离可测且有/无归还 |
| **fidelity 曲线** | 每小节"离骨架多远"。**离题是否成立靠它，不靠形容词** |
| **接缝 seam** | 拼接处的人为接口（共同音 / 枢轴 / 静默 / 硬切） |
| **词层** | 字-音绑定 + 咬字 + 句读。唯一携带语言的那一层 |
| **遮蔽 masking** | 其他声部同时占住主声部的音区与节奏，导致字听不清 |
| **passaggio** | 换声区。人声独有的危险音区 |
| **舒适区 comfort** | 乐器/演奏者覺得好聽且能持久的音域。推荐值来自 `instruments/`，可被座位覆盖 |
| **pin** | 人钉住的音符、乐句或路径点，免疫于重新生成。 |
| **affect 向量** | 情绪 → 参数的中间形式（价值度、能量、密度、张力…），不是形容词本身。 |
| **词表 lexicon** | affect 词 → （空间偏好 / 路径形状 / 织物参数）三列的映射表。项目核心资产。 |
| **lint** | 可演奏性/可听性检查：单音限制、换气、音区碰撞、平行五八度… |
| **内环** | 改→听，≤2 秒，离线，无 GUI。 |
| **外环** | 导出 → 精修 → 排版 → 分发。分钟级，人工。 |
