# Composer

把「悲伤」「要强烈」「像某首歌」这类抽象想法，变成**能立刻听见、能看见、也能自己验证**的编曲草稿。

---

## 0. 这份文档

**唯一的一份。** 只装结论，不装过程——过程在 git 里。

它记录：相信什么（哲学）、被什么约束（硬约束）、认为音乐是什么（模型）、现在能做什么（能力）、还有什么没解决（待决）。

## 1. 问题

### 1.1 真实的问题

表面的说法是"不想在 MuseScore 里一个音符一个音符点鼠标"。那只是症状。

> **从「脑子里的感觉」到「听到的声音」之间，有一条不可观测、不可验证的鸿沟。**

你清楚"这段要压着，副歌才炸"，但这个判断在变成声音之前无法检验，而且你也说不清它由哪些部分构成。

### 1.2 为什么"让 AI 直接吐音符"会失败

| 失败 | 表现 | 根因 |
|---|---|---|
| **不可指认** | "有点怪，但说不出哪怪" | 说不清哪里不对，就无从改起 |
| **不可定位** | "再悲伤一点" → 整体重写 → 开盲盒 | 没有可调的参数，只有重新抽样 |
| **不可验证** | 对不对只能靠反复听 | 意图的后果没有被测量 |
| **迭代太慢** | 改一次要开 GUI、等加载 | 重工具进入了开发循环 |
| **不可积累** | 好版本留在聊天记录里，下次重来 | 成果不是仓库里的资产 |

### 1.3 我们要做的

> **可持续、可迭代、可尝试、允许犯错的编曲模式。**

注意这里面**没有"收敛"**。创作至少有三种迭代，而它们的目标不同：

| 模式 | 在做什么 | 收敛吗 |
|---|---|---|
| **优化** | 逐渐接近一个已经存在的目标 | 是 |
| **发现** | 试听之后，才知道自己原来想要什么 | **不** |
| **偏离** | 放弃原来的目标，换一个 | **不** |

把收敛当成唯一指标，会逼系统往用户已经能想象的东西上跑：保留已认可的元素、不敢做破坏性修改、把探索空间压成局部搜索。而很多音乐创作恰恰需要删掉已经喜欢的部分、推翻上一轮、突然换编制、让合理的段落变得不合理。

所以审判设计的不是"有没有更接近"，而是两条**与目标无关**的性质：

> **每一步都可逆（退得回去），每一步都可指认（说得出改了什么）。**

这两条不需要知道目标，所以发现和偏离时照样成立；而且它们**正是破坏性探索的前提**——正因为退得回去，才敢乱来。

## 2. 第一原则

**P1｜闭环是产品，表示层是资产。**
AI 生成音符不值钱。值钱的是那个中间表示：既能让语言落到可调的参数上，又能确定性渲染成声音与乐谱。

但**资产不能代替产品**。用户不会因为 YAML 漂亮、diff 严谨、变换血统可追溯就觉得好用；他只会因为"听完之后能马上试下一个想法"而留下。表示层是快循环的前提（不能只改一件事，就只能重新生成），不是它的替代品。

**P2｜可逆 + 可指认 > 更接近。**
宁可生成能力平庸但"退得回去、说得清"，也不要一次惊艳但无法复现。

系统不预设迭代方向（优化 / 发现 / 偏离都合法），只保证：任何一步都能退回，任何一步都能被一句话指认。

**P3｜模糊意图必须可分解为可度量的音乐后果。**
"悲伤"不是音符，是一组跨声部的**方向**（密度、音区、音程、解决延迟…）。这张分解表是项目的真正资产——不是 prompt，不是 API。

**P4｜反馈必须可测量，但测量只用于定位，不用于评分。**
系统要能说出"三件乐器挤在 C3、长号这句没有换气口"。但它**只负责指着让你看**，不负责告诉你该怎样。

**P5｜听见 + 看见 是产品界面，乐谱不是。**
乐谱、分谱、打印都发生在验证之后，属于外环。

**P6｜时间预算决定架构。**
内环（改→听）必须 ≤ 2 秒且完全离线；外环可以是分钟级人工操作。**任何重型 GUI 软件进入内环，都是架构错误。**

**P7｜资产，不是对话。**
编曲必须作为可 diff、可复现、可分享的文件活在仓库里。

**P8｜诚实抽象。**
不确定的事绝不假装确定。不返回假的 success，不提供"看得见但没生效"的操作，不用"看起来对"掩盖语义漂移。**歪掉的成功比明确的失败昂贵得多。**

**P9｜现实的人。**
乐器有呼吸、有指法、有把位、有体力；演奏者之间舒适区不同。可演奏性是硬约束，也是通用 AI 音乐工具给不了我们的差异点。

**P10｜人是最终裁决者。**
系统的任何输出都只是**候选**。判断不可外包、不可优化、不可代理。由此推出的不是保守，而是相反：**模型可以大胆到不讲道理，只要判断足够便宜**。绝不用"怕平庸"收窄搜索空间。

**P11｜编制是调色板，不是清单。**
乐器是颜料，不是必须出现的颜色。**某个声部不出现，是合法的、而且经常是最强的手段。**

**P12｜空与未决是一等值。**
`absent` 和 `undecided` 都必须能写下来、显示出来、被保留。系统**不得为了完整而自动填补**。
允许编不出来——这个项目本来是"验证一个 idea 行不行"，那么"不行 / 不知道"当然是合法答案。

**P13｜没有必须主导的那一个。**
不允许任何乐器或人声被声明为"整曲的主导"，那是先验指派。

- "谁被听见"**不是输入，是测量**。
- 编排的对象不是声部，是**声部之间的关系**：对答、接力、互补、叠置、让位、影子、碰撞。
- 关系层**只测量、只描述，不禁止**——"齐奏"与"糊"在很多数字上长得一样，只有耳朵能分开。

> 人声的特殊性不在"主导"，而在**携带语言**：有词人声与别的声部撞了，语言会被吃掉，那是硬约束。
> 但"有词人声必然优先"同样是流行音乐的默认假设，不是原则。

**P14｜输入是骨架，不是成品。**
一首歌、一段动机、一条和声进行、一个情绪诉求，都只是**骨架**。骨架之上应当能长出更丰满的东西，包括**离题**与**拼接**。

**P15｜历史不当偏好。**
系统**永不根据历史推断用户想要什么**。四种东西必须分开：

| | 是什么 | 允许吗 |
|---|---|---|
| **记录** | 过去产生了什么 | ✅ |
| **去重** | 两个候选是不是重复 / 提示曾经探索过 | ✅ 但**不得阻止重复** |
| **pin** | 用户明确承诺保留什么 | ✅ 这是创作权的表达 |
| **偏好推断** | 系统推断你喜欢什么，并自动改变未来结果 | ❌ 永不 |

> "过去三次都是钢琴开头，所以这次避开钢琴"——这已经不是去重，是策略改变。
> 而且**重复本身可能就是创作行为**，去重不能把它禁掉。

## 3. 音乐模型

*（这一节回答的不是"用什么格式存音符"，而是"我们认为音乐是什么"。）*

### 3.1 一句话

> 一首曲子 ≈ **在状态空间里的一条轨迹**，由**意图参数化的政策**驱动，最后**织成音符**。

### 3.2 两个来源，一个合成

**来源一：音乐是时间的函数**（Tidal/Strudel、FRP、Xenakis 的随机音乐）。
得到：可采样（任意 t 求值 → 循环、A/B、跳小节、离线导出）、参数自动化免费、组合性。
缺陷：纯时间函数是**预先写死**的，无法表达"这个动机，移到当前和弦上"——因为"当前和弦"不是它的自变量。

**来源二：音乐是在和弦空间里的游历**（Tonnetz / 新黎曼 / Tymoczko / Xenakis 的 *outside-time*）。
得到：声部进行 = 求最近邻；转调代价可算；大尺度形式与小尺度和声统一；情绪 = 期待的建立与兑现（Huron）。
缺陷：只回答和声，对鼓、音色、节奏密度一言不发。

**合成：柯里化。**

```
F : (Time, HarmonicState, AffectState, MaterialState, RelationState) → Event*
```

- **L1 规格** = `F` 的参数 + 和声语法 + 意图取值
- **L2 事件图** = 固定其余自变量后，`F` 退化为纯时间函数，求值即得

意义：**"写死的音符"与"随上下文变形的音符"在同一个模型里共存**——前者是常数函数，后者依赖 H。素材猜错时编排逻辑不受影响。

> ⚠️ **这个公式是图示，不是公理。**（见 §11）
> 自变量列得再全也装不下真正的生成上下文：此刻应该回应上一句长号、接续小提琴的动机，还是保持沉默？
> **时间不是上下文**——知道现在是第 37 秒，不等于知道该做什么。
> 它的价值只在 **L1 / L2 之分**，不在自变量清单。

> **记谱语言是值域（codomain），不是载体（carrier）。**
> 它记录 *what*（哪个音、多长、怎么连），天生丢掉 *why*。
> 所以**别在记谱语法上设计任何东西**，只在最后一步做无损编码。

### 3.3 四个层

```
   意图 A ──► 政策 Policy      怎么走：多快、多远、哪里停、要不要跳
                  │
   规格 S ──► 空间 Space       哪些状态可达：和声/节奏/音区/在场的语法
                  │
                  ▼
             轨迹 Trajectory   γ : [0,T] → Space   具体的游历
                  │
             织物 Texture      每件乐器此刻做什么（角色生成器）
                  │
                  ▼
                 L2 事件图
```

| 层 | 是什么 | 谁决定 |
|---|---|---|
| **政策** | **怎么走**：跳/邻、快/缓、延迟/即时解决 | 情绪词 + 人 |
| **空间** | **哪些状态可达**：语法与约束 | 调式/和弦字典/节奏文法 |
| **轨迹** | 具体的游历 | 政策驱动，人可 pin |
| **织物** | 音符级实现 | 角色生成器 |

**关键推论："YAML 还是 Strudel"的争论落在了错的层。** 音符文本只负责最内一层的织物。

### 3.4 形式与和声可能是同一个路径的不同尺度

假设：段落安排与和声进行是同一个"路径"在不同尺度上的投影。
"副歌要炸" = 抵达一个远处然后解决；"主歌压抑" = 在原地徘徊。

> ⚠️ **这是假设，不是结论。**（见 §11）
> 反例就在本曲里：它的形式来自**在场路径**（谁进来、谁退场），与和声进行关系不大。
> 形式还可能来自主题重现、音色变化、突然中断、歌词叙事。
> 过早把宏观与微观统一起来，会得到数学上的优美和音乐上的失血。

### 3.5 情绪词是**位移**，不是坐标

人从不说"我要 0.8 的悲伤"。人说 **"再悲伤一点"**。

所以情绪词不是三列坐标，是**叠加在当前位置上的方向算子**：

| 词 | 候选方向（**假设，不是映射**） |
|---|---|
| 更悲伤 | 密度 ↓、音区 ↓、音程 ↓、解决 ↓（延迟） |
| 更强烈 | 密度 ↑、音区 ↑、动态 ↑、跳跃 ↑ |
| 更空 | 在场集合 ↓、留白 ↑ |
| 更紧 | 节奏重合 ↑、交错 ↓、力度一致 ↑ |
| 更远 | 和声距离 ↑、离骨架 ↑ |

> ⚠️ **这张表是候选生成器，不是翻译器。**（见 §11）
> 降音区可以悲伤、可以温暖、可以威胁、也可以滑稽；减少密度可以更空，也可以失去力量。
> 这不是测量误差，是音乐语境本身的性质。

所以正确的用法是**一次提三个假设**，而不是执行一个映射：

```
意图：更悲伤
候选：A 只降音区    B 密度 + 音区    C 和声模糊 + 解决延迟
你来听：哪个成立？
```

差别很大：前者是情绪翻译器（声称知道），后者是音乐实验工具（提出假设）。后者才符合 P10 与 P12。

表里每一条都必须标 **未验证**，直到被听过。听过且成立，才从假设升为经验。

每个算子只需要**方向 + 比较**，不需要数值。方向来自人的成对判断（"这个比刚才对"），不需要人给出任何刻度。

**数字只允许出现在中间**：

```
人的直觉 ──────── 感受，无单位            ✗ 不能放数字
    ↓
方向算子 ──────── 更密/更疏、更高/更低     符号，不是数值
    ↓
生成器参数 ────── 密度/音区/力度/在场集合   ✓ 数字只在这里
    ↓
渲染
    ↓
人的判断 ──────── 更好 / 更差 / 换方向      ✗ 不能放数字
```

> 为什么感受无法量化：人对**绝对量**的判断既不稳定也没有意义，对**差分**的判断却很快很一致。
> 所以系统永远只需要"往哪边"，不需要"到多少"。

### 3.6 因此可计算的东西

| 指标 | 由什么导出 |
|---|---|
| 张力曲线 | 状态与"家"的距离 + 路径导数 + 不协和度 |
| 走远了没有 / 有没有回家 | 路径的位移与回归 |
| 声部进行是否平滑 | 和弦空间中的距离（Tymoczko） |
| 等音拼写（G# 还是 Ab） | 在和弦空间里选最近的表示 |
| 离骨架多远 | 见 3.12 |

### 3.7 空间的四轴

原先只有和声一条，这是模型最大的缺口：**"进行曲"和"恢宏"有一半写不出来**，因为它们不是和声概念。

| 轴 | 内容 | 可用理论 |
|---|---|---|
| **和声** | 功能、借用、转调 | Tonnetz / 新黎曼 / Tymoczko |
| **节奏 / 节拍** | 律动、重音、错位、欧氏 | Krebs 的节拍错位理论 |
| **音区 / 织体** | 密度、音区占用、留白 | 基本空白 |
| **在场 presence** | 谁在响、谁不在 | 无既有理论 |

> 注意「音区」在这里有两个意思，必须拆开：**素材音区**（主题此刻坐在哪、跳了多远，属骨架层，见 3.12）与**织体音区**（所有声部的分布与拥挤程度，属空间层）。
> 它们会打架，而打架是有价值的：主题升八度 → 撞进别的声部上方。

#### 在场空间

> **配器 = 在「编制幂集」（2ⁿ 个状态）里走的一条路径。**

- **空集是合法状态。** 静默不是"没有设计"，它是空间里的一个点。
- "不出现"与"出现"是同一机制的两种取值。
- 于是"恢宏"可以写成 **"从 1 件到 3 件用了 8 小节，再一次性到满编"**，而不是 `density: 0.8`。
- **连续密度旋钮的形状是错的**：它假设"大家都在、只是弹得稀"，而真相是**"谁不在"才是主武器**。

实证来源：贝多芬第九末乐章——《欢乐颂》的主题**第一次出现是裸的、轻的、单声部的**，全场力量来自随后逐层加厚。

### 3.8 模型的边界

- 四条轴彼此独立，"悲伤"这类词需要同时落在几条上，而不是一条。
- **最短路径 = 最平庸的音乐。** 距离必须是被意图控制的**参数**，不是被最小化的目标——"强烈"就是允许大跳。
- 三元和声的文化局限：四度叠置、音簇、调式混合，新黎曼理论都很勉强。
- **形式化 ≠ 动人。** 这个模型保证的是**连贯**，不是**感染**。

> 最后一条不是要规避的风险，而是**已接受的代价**（P10：模型可以大胆，判断必须便宜）。

### 3.9 参考谱系

| 谱系 | 给我们的 |
|---|---|
| **Xenakis**：*outside-time* / *in-time* | L1 / L2 之分 |
| **Tonnetz / 新黎曼**（Cohn, Fiore） | 和弦是格点，P/L/R 是移动；转调 = 走位 |
| **Tymoczko《A Geometry of Music》** | 和弦空间 = 有序音高元组的商空间；距离 = 声部进行的平滑度 |
| **Huron**：期待理论 | 情绪 = 预测的建立、违反与解决 |
| **Tidal / Strudel** | 时间函数 + 可采样 + 参数自动化（作投影，不作真源） |
| **Sorensen / Extempore** | 代码即数据 → 免费的可寻址性；变更落在下一个音乐边界；单声部热替换不中断时间基 |
| **算法作曲传统**：Common Music / OpenMusic / Slippery Chicken | "结构化描述 → 生成 → 乐谱"这条管线，比 live coding 更贴我们的问题 |
| **Abjad** | 出口层首选试验对象：精确控制连音线/符杠/嵌套 tuplet |

### 3.10 人声

四层装得下"人声这件乐器"，**装不下它的文本**。

| | 是什么 | 模型里有吗 |
|---|---|---|
| **作为乐器** | 单音、受呼吸限制、个人音区，**还有换声区（passaggio）** | 部分 |
| **作为文本** | 字-音绑定、咬字、句读。**唯一携带语言的声部** | ❌ |
| **作为叙事** | 谁在唱、哪一句是"点" | ❌ |

**两个自变量，不要揉在一起**：`text: true/false` 决定约束的重量；是否人声决定音色与演奏法。**"谁主导"不是变量**（P13）。

于是"人声"不是开关，而是四种合法形态：

| | 它在听感上突出 | 它退在后面 |
|---|---|---|
| **有词** | 流行歌（默认假设） | 伴唱 / 和声 / 念白 / 器乐曲中的人声插段 |
| **无词** | 阿卡贝拉化 hook、哼鸣主题 | 氛围层（ooh/aah）、音色层 |

**四种都要能写得出。写不出哪一种，模型就是错的。**

模型补充：

1. **voice 类型**：`range` / `comfort` / **`passaggio`** / `text: true` / `breath: strict` / `stamina`。
2. **词层**：每小节的 `degrees` 旁边挂一行 `text`，一一对应，破折号表示一字多音。这本来就是中文乐手写简谱的方式。
3. **叙事计划**：谁在唱、什么状态（solo / 三度和声 / 同度齐唱 / 无伴奏 / 无词）。
   **和声人声不是独立写的**：从 lead + 和弦派生（取上方最近的弦内音，且间隔 ≥ 三度）。

lint（按条件适用，不一律上刑）：遮蔽 / 呼吸 / 咬字 / 换声区 / 和声正确性。

**歌词决定走向**：行的语义重量 → 全员在哪里落；音节密度 → 乐句长度；一字多音的位置 → 往往是情绪顶点。
（《送别》四句词逐字对上了旋律，拖腔 ≥2 音的三个字是 **天 / 落 / 寒**——语义最重的三个字，正好是旋律拖长的地方。）

### 3.11 关系层：编排的对象是"对"

四层都是**关于单个声部**的。但"化学反应"发生在两个声部之间。

| 关系 | 描述 |
|---|---|
| **对答** | A 动 → B 动，交替 |
| **接力** | 同一动机换手 |
| **互补 / 交错** | 两者都不完整，合起来才成形 |
| **叠置** | 有意同度 / 八度 |
| **影子** | 错开半拍到一拍的同一条线 |
| **让位** | 一个退场，另一个浮现 |
| **碰撞** | 同节奏 + 同音区 + 同动态 |

可测形式：节奏重合、**交错度** `(|A∪B|/网格)×(1−重合)`、同时发声的音程中位数、同度/八度率、音区重叠、轮廓关系（同向/反向/斜向）。

**唯一的硬规则**：有词人声参与的碰撞。理由不是审美，是**信息**——字被盖住，语义就没了。

### 3.12 骨架、忠实度、离题

**骨架 = 如果拿掉它，这就不再是它的那些东西。** 它不预设类型，只看一件事：你愿意为它放弃多少自由。

#### 骨架是分层的

| 层 | 形态 | 可测吗 | 例 |
|---|---|---|---|
| **素材** | 音符 / 节奏 / 和弦 / 词 / **音区** | **高**（轮廓重合、动机匹配） | 送别的 20 小节 |
| **结构** | 小节数、段落边界、顶点位置 | **高** | 顶点在第 15 小节 |
| **关系** | 两件乐器怎么交织 | 中 | 贝斯锁 kick |
| **感受** | **约束**（"不许比现在更平淡"），不是目标值 | 只能验方向 | —— |

> **感受层不能是数值目标。** 人对绝对刻度没有体感，给"能量 0.95"是自欺。
> 它只能以**约束**的形式进骨架：拿两版在可观测量上比方向，而不测量感受本身。

骨架通常是**拼起来**的：素材来自源、感受来自委托、结构可能来自任何一方。本曲就是这样——《送别》给素材，"恢宏/进行曲"给感受。

#### 素材是一条独立的时间线

现在（错误地）旋律是"小提琴的一个段"。这一行字同时说了两件事，而它们必须分开：

```
素材轨 material track   什么音乐，在哪几小节        ← 骨架层
     ↓ carries
声部 part               谁演奏，什么音区，什么音型   ← 渲染层
```

```yaml
material:
  - id: melody
    pin: frozen
    timeline:
      - {bars: "5-8",  use: farewell.p1}
      - {bars: "9-12", use: farewell.p2}

  - id: intro_fig                 # 无来源轨：编排自己写的素材
    source: null
    timeline: [{bars: "1-4", notes: "0:4 1:4 0:4 5,:4"}]

parts:
  violin: {carries: [{bars: "5-24", track: melody}]}
```

三条由此落定的规则：

- **同度齐奏 = 多个声部承载同一条轨。** 素材只有一份，不会不一致。
- **八度叠置 = 多条素材实例**（`use` + `op` 指回原轨），不是给 `carries` 加参数。
- **自由音符也是轨**（`source: null`），不是特殊路径。于是"骨架 / 派生 / 外料 / 自由"是同一结构的四种来源类型。

#### pin 写在骨架节点上

```
✗  pin 在 parts[violin].segments[5].degrees   → 旋律和小提琴焊死，换乐器就是重写
✓  pin 在 material.melody                     → 骨架不动，谁演奏它渲染时再定
```

pin 不是 boolean，是骨架节点上的字段（`pin: frozen`）。**如果需要钉住半个 cell，说明 cell 切得不够细**——那是结构问题，不是语法问题。

#### 八度属于素材层

八度不是中性位移。**突然升一个八度是效果**（"激烈的"）；如果它只存在于渲染时，这个效果就既不可写、也不可复现、也无法解释为什么这一版不一样。

所以素材实例自带音区，**承载者不许再声明 octave**。

| 情形 | 表达 | 结果 |
|---|---|---|
| 同度齐奏 | 多声部承载同一轨 | `register_delta = 0` |
| 八度叠置 | 另一条实例，`use` + `op: [{octave: -1}]` | `register_delta = ±12` |
| 承载者够不着 | **报差距**（C14），不自动降 | 人显式声明 `melody_low` |

#### 位移可以写量词，但必须分类

两类词必须分开：

| | 例子 | 有客观量吗 | 允许写量级吗 |
|---|---|---|---|
| **感受词** | 悲伤、激烈、空 | 没有 | **永远不许**（只写方向："更…"） |
| **量词** | 一点点、稍许、更多 | 有（半音 / dB / 音符数） | 允许，但必须落到数 |

```yaml
axes:
  register:
    unit: semitone
    degrees: {一点点: 2, 稍许: 5, 更多: 7, 一个八度: 12}
```

词是糖：加载时立刻解析成数值，下游只见数——歧义只存在于书写的一瞬间。数字逃生口永远保留（`register: +12` ≡ `register: 一个八度`）。

**但"变高"有两种完全不同的性质：**

| 位移 | 音级关系 | 是纯音区吗 | 标记 |
|---|---|---|---|
| ±12、±24（整八度） | 不变 | ✅ 是 | `tonal: false` |
| ±1…±11（五度、全音、半音） | **变了** | ❌ 这是**移调** | `tonal: true` |

非八度位移**允许**（它是有力的手段），但系统必须报出来：

> `稍许` = +5 半音：这是移调，不是音区。旋律到了 F，和声仍在 C。若无意如此，请用 `一个八度`。

#### 两条位移都算

```yaml
bar 25:
  register: +12
  delta_vs_prev_bar: +12           # 抓"突然跳"
  delta_vs_last_appearance: 0      # 抓"再现时变了"
  tonal: false
```

前者抓突发，后者抓回归。**"同样的素材、回来时高了一个八度"** —— 这是发展部最核心的手法，而且不需要离题，只靠音区：

```yaml
- {bars: "21-24", use: farewell.p5}
- {bars: "25-28", use: farewell.p5, op: [{octave: 1}]}
```

#### 变换链

派生不是"再写一遍类似的"，而是**对已有素材做一次可指认的变换**。`op:` 是一个链，从左到右作用：

| 算子 | 作用 | 位移性质 |
|---|---|---|
| `octave: n` | 整体移八度 | 纯音区 |
| `transpose: n` | 移半音 | 移调（`n % 12 ≠ 0` 时） |
| `invert: first\|n` | 旋律倒影，轴缺省 = 第一个音 | 音级关系改变 |
| `retrograde` | 时值倒影 | 保持 |
| `augment: k` / `diminish: k` | 时值伸缩 | 保持 |
| `fragment: [a, b]` | 取音序号区间 | 保持 |
| `sequence: {step, times}` | 模进：重复并逐次移高 | 移调 |

三条硬规则：

1. **每个派生都必须能说出血统**（“这是第 3 句的倒影”），否则 fidelity 无法追溯，派生与新写的东西在数据上无法区分。
2. **变换改变长度时必须报差距**（C14）：`augment: 2` 需要 8 小节而只给了 4 小节 → 报错，不默默截断。
3. **除不尽就报错**，不要四舍五入：`diminish: 3` 在 16 格网格上写不出 4 步的音。

#### 改编 = 换掉某一层，保持其余层

| 动作 | 换 | 保持 |
|---|---|---|
| 移调 | 素材的音高 | 轮廓 |
| 重新配器 | 关系 | 素材 + 感受 |
| 换情绪 | 感受 | 素材 |
| 拼接 | 素材 | —— |

#### 四档忠实度

| 档 | 定义 | 判据 |
|---|---|---|
| **骨架** | 源材料本体 | 旋律音 / 词 / 结构 |
| **派生** | 由骨架经**可指认的变换**得到 | 能说出"这是第 3 小节的倒影" |
| **离题** | 素材不可追溯，但**感受/结构还在** | 距离可测 + 是否归还 |
| **外料** | 引自他处 | 显式引用 |

**离题 + 归还 = 发展部；离题 + 不归还 = 拼接。** 同一个机制，只由"是否归还"区分。拼接真正要设计的是**接缝**（共同音 / 节奏枢轴 / 持续音 / 静默 / 过门遮盖 / 强行硬切）。

#### fidelity 是向量，不是标量

把轮廓、节奏、音区加权成一个 0–1 分，就是"能量 0.95"的翻版：权重是编的，而且"轮廓 0.9 但降了八度"和"轮廓 0.8 但音区对"会被压成同一个数。

所以分开报，**让耳朵加权，不让代码加权**：

```yaml
bar 19:
  contour: 0.94                    # 移调/移八度不变的音程序列重合
  rhythm: 1.00
  text: ok
  register: -12                    # 半音，相对源
  delta_vs_prev_bar: 0
  delta_vs_last_appearance: -12
  tonal: false
```

**N/A ≠ 0。** 引子没有源，不是"离骨架最远"，是"不在骨架里"。

它只对**素材层与结构层**成立，对感受层不成立。用途是**定位**：

- **意外离题**：作者以为在写主题变奏，实测已经听不出来了。
- **离题不归还**：掉下去就没回来 = 拼接，可能是有意的，也可能不是。

> **素材身份由人主张，系统只举证。**
> 一条旋律改到只剩三个音、节奏全变、轮廓只剩暗示——它还是不是原素材？
> 这是创作判断，不是距离计算的结果。
> 系统可以报“轮廓 0.62、节奏 0.40、原音区偏了 7 半音、关键节点保留 3/5”，
> 但**永远不得因此自动宣布“这已经不算送别”**。

#### 交叉检验：声明 vs 实测

fidelity 的计算依据是**声明的承载者**，不是显著度检测——否则它会继承显著度的错误（§8 B2）。

但声明的危险是：你可以声明小提琴在演奏主题，而它实际被埋在 9 dB 以下。所以两者都要，角色不同：

| | 角色 |
|---|---|
| 声明的 carrier | fidelity 的计算依据 |
| 实测的分量表 | **交叉检验**：声明在演奏 vs 实际听不见 → 报一条 lint |

而且**不计算单一"显著度"分数**——那是同一个坍缩错误。报分量：

```yaml
bar 17:
  violin:   {sounding: 4.0, rms_db: -18, register: "G4-C6", text: false}
  piano:    {sounding: 8.0, rms_db: -12, register: "C3-C5", text: false}
```

于是 lint 只做一件很窄的事：

> 你声明小提琴在第 17 小节承载 melody；实测它比钢琴低 6 dB，且钢琴占住同一音区。

这样 B2 不是被修好，而是被**消解**——"谁最突出"这个问题被取消，替换成一张分量表。

## 4. 架构形状（暂定，未锁定）

```
      「悲伤」「像《Creep》」「副歌进长号」
                    │
         ┌──────────▼───────────┐
         │ L0  意图层            │  语言 / 情绪 / 参考曲 / 叙事
         │     + 情绪词表(lexicon)│  → 归一化为方向算子
         └──────────┬───────────┘
                    │  LLM 只在这一层工作
         ┌──────────▼───────────┐
         │ L1  编曲规格 Spec     │  ★ 唯一可编辑真源
         │  骨架 + 空间 + 政策    │  树形、可寻址、可 diff、可回滚
         │  + 轨迹约束 + pins    │
         └──────────┬───────────┘
                    │  确定性生成器 + 演奏法约束 + 关系
         ┌──────────▼───────────┐
         │ L2  事件图 NoteEvents │  构建产物（可被 pin 覆盖）
         └──┬────────┬────────┬──┘
            │        │        │
         音频渲染  可视化  分析与 lint
         (内环)   (钢琴卷帘) (关系/分量表/音区/可演奏性)
            │
            └──────► 出口：MusicXML / MIDI ──► MuseScore / Guitar Pro / DAW
```

### 三层权威

1. **Pinned** —— 人钉住的骨架或路径点，**永远赢**。
2. **Generated** —— 由「政策 + 空间 + 角色 + seed」确定性生成，占绝大多数。
3. **Inferred** —— 从意图推出的默认值，可被上面两层覆盖。

> 如果一条设计让人无法"钉住某个乐句"，它就是错的。

### 双环

- **内环**：改参数 → 重生成 → 合成 → 听 / 看 / 测量。秒级，无 GUI，可 headless。
- **外环**：导出 MusicXML → MuseScore / Guitar Pro 精修、排版、打印、发给乐队。

## 5. 硬约束

**C1｜编制是输入，不是常量。**
代码里不允许出现固定人数。谁在场、音域、舒适区、惯用音型、是否单音——全部来自 `ensembles/*.yaml` + `instruments/*.yaml`。加人、减人、换乐器**不改代码**。

音区分三层：`range`（越界 = 错误）/ `comfort`（越界 = 提示）/ 座位 `overrides`（优先于推荐值）。
"推荐"是系统给的，最终是演奏者说了算（P10）——所以它必须是**座位**的属性，不是乐器类型的绝对真理。

**C2｜内环不依赖任何重型 GUI 软件。**
**C3｜确定性可复现。** 同一份 Spec + 同一 seed → 逐事件相同。
**C4｜修改是结构补丁，不是文本重写。** Spec 必须是有稳定路径的树；一次修改 = 「路径 + 新值」。**只能被文本重写的东西（如代码）不适合当真源。**

> 作用域：这条约束的是**系统内部的修改语义**，不是用户怎么改。
> 在钢琴卷帘里拖音符、导入一份新 MIDI、在 DAW 里改完拿回来——都合法，系统必须能重新理解并纳入版本历史（见 §10 Q6）。

**C5｜人类干预优先。** 手改结果不可被下一次生成默默吞掉。
**C6｜双环境可跑。** headless 与浏览器都能驱动同一条管线。
**C7｜出口用通用格式。** MusicXML 优先，MIDI 用于试听与 DAW。不为任何单一软件写专用适配器。
**C8｜说用户的词。** 中文情绪词、参考曲名、简谱式数字音级（`1 2 3 5`、`0` 为休止）。
**C9｜改动量化到音乐边界。** 变更在下一个拍或小节边界生效；内环的时间基永不中断，声部可热替换。
**C10｜让判断变便宜。** A/B、段落循环、单声部 solo、多候选并排，属于核心基础设施。
**C11｜不存在全局权重常数。** "哪一层更重要"是词条级/段落级变量，不是定律。
**C12｜全员段需要的是“同向”，不是“同音”。** 厚重感可以来自齐奏与八度叠置，也可以来自密集叠置、多个节奏同时到达峰值、低频能量、音色宽度、不协和度。

> ⚠️ 原表述“厚重感来自同音与八度叠置 + 低频相位一致，不来自声部数量”已降为**假设**（见 §11）：它基于一个样本，且相位一致是**混音属性**，不是作曲属性。
**C13｜约束挂在"对"上，不挂在层级上。** 不设全局焦点，不设"人声优先"。两件同节奏 + 同音区 + 同动态 = 碰撞（提示，不是错误）。
**C14｜达不到就报差距，不自动加料。** 骨架/约束达不到时，说"这里只到 X"，不要为了达标而堆料——那会把手段变成目的。
**C15｜量词只在有单位的轴上。** "稍许/更多"这类词只允许落在半音、dB、音符数上；感受轴永远没有刻度。
**C16｜音域适配不得自动。** 承载者够不着素材的音区时，报差距并由人显式声明位移。自动降八度会让"为什么这一版不一样"永久无法追溯。
**C17｜每个概念都必须能翻译成一个音乐动词。** `carrier` / `op` / `trajectory` 这些词是给实现用的，不是给人用的。如果某个概念说不出对应的动作（"把这段给长号"、"移高八度"、"让鼓晚半拍进来"），它就是给用户加的税，而且会让 diff 读不懂。
**C18｜测量分三类，永不混淆。**

| 类 | 内容 | 系统的态度 |
|---|---|---|
| **硬错误** | 超出物理音域、事件非法、变换装不下、除不尽 | 阻止 |
| **风险提示** | 歌词被遮蔽、换气不足、音区重叠 | 提示，可忽略 |
| **描述性测量** | 密度、动态、音区、重合度、位移 | **只是事实，永不进 lint** |

> 特别写死一句：**“旋律太平”“缺少变化”“和弦不够丰富” 永远不是警告。**
> 音乐可以故意平、故意重复、故意不丰富。可测不等于重要；系统不断展示它能测的东西，用户就会开始优化那些指标。

## 7. 表示层：已落地的选择

**树形 Spec（YAML）为主真源 + 内嵌简谱式 `degrees` 字符串。** 试听投影（Strudel）与记谱出口（MusicXML）尚未实现。

```yaml
# 骨架：什么音乐，在哪几小节（与谁演奏无关）
material:
  - {id: melody, theme: true, register: 4,
     timeline: [{bars: "5", degrees: "5:4 3:4 5:2 8:2 7:4"}]}
  - {id: melody_low,
     timeline: [{bars: "17-22", use: melody, op: [{octave: -1}]}]}

# 渲染：谁演奏它
parts:
  - {instrument: violin, carries: [{bars: "5-24", track: melody}]}
  - {instrument: ewi,    carries: [{bars: "17-22", track: melody}]}       # 同度齐奏
  - {instrument: lead-guitar, carries: [{bars: "17-22", track: melody_low}]}  # 低八度

# 声部自己的音型（不由骨架承载）
- {bars: "17-22", pattern: {pitch: frame, rhythm: "x---------------"}}
```

结论：

- 简谱式字符串**好写**，一行一小节，逐音可核对；没有被迫造语法。
- 可寻址**成立**：改钢琴一个词（`wide` → `frame`）就解决了中频碰撞。
- **素材与声部已分离**：旋律只写一遍，三个声部各自声明承载它。同度齐奏与八度叠置不再靠复制粘贴。
- 平台期在**节奏的书写**：字符串只有固定步数，三连音/复节奏写不出来（见 §8 B4）。

## 8. 现状

### A. 已验证能做到

| 能力 | 证据 | 证据的边界 |
|---|---|---|
| 简谱 + 歌词 → 可听的九人编曲，52 秒 | `samples/` | 只有一首曲子、一种风格 |
| 全流程秒级、无重型依赖 | render 0.1s + fluidsynth 0.15s + 零依赖合成 0.9s | 24 小节；上百小节未测 |
| 在场路径可声明、可双向校验 | 有音符但未声明 / 声明但无音符，两种都报 | 只有**整小节**粒度 |
| 动态曲线可声明并实测 | −73 dB → −23（全员）→ −45（拆人）→ −19（最后一击） | 只在段落边界变，小节内不能渐强 |
| 音区三层 + 自动择位 | 长号算出"不移位"是对的 | 只按八度平移，不换把位 |
| 和声拼写自检 | 抓到过"Am 被渲染成 C 小调"的真 bug | 只查音级，不查声部进行 |
| 成对关系测量 | 抓到 Piano × Violin 中位 7 半音，改后 14 | 只能**测**关系，不能**造**关系 |
| 可复现 | 同 spec 渲染两次，MIDI md5 相同 | 只对当前实现成立 |
| 编制是输入 | 加钢琴、拆两把吉他，都只改 YAML | 座位能力还只是元数据，未进生成器 |
| **骨架与编排已分离** | 旋律只写一遍；小提琴/EWI 同度齐奏、Lead Guitar 低八度，全从 `carries` 得出 | 只有一条主题轨、两种承载方式；变换与 fidelity 未接 |
| **听、比、改的闭环（C10）** | `audition.py`：小节循环、solo/mute、A/B、盲测、结构 diff。小节范围 0.24–0.61 秒 | 播放依赖系统音频服务；没有交互界面，没有多候选自动生成 |

### B. 已知薄弱

| 薄弱处 | 表现 | 为什么还没修 |
|---|---|---|
| 声部进行是"最近邻" | 长号连续十小节停在同一个共同音 | 纯最小化 = 退化；需要"何时允许跳" |
| 显著度 ≈ "最忙的" | 全曲都报电贝斯，人耳听的是小提琴 | 不修——**取消单一显著度分数**，改报分量表（§3.12） |
| 交错度奖励"一疏一密" | 鼓 × 长号排第一，那不是 hocket | 需在同一拍位上算空隙 |
| 节奏书写只有固定步数 | 三连音、复节奏、摇摆写不出来 | 需要可变 subdivision；**数据模型其实不限制**（480 tick 能整除 3 和 5），只是书写语法窄 |
| 等音拼写是全局降号 | C 大调里的 G# 写成 Ab | 应由和声上下文决定（§3.6） |
| 音源是 GM | 音色判断不可靠，人声更没法 | 草稿够用，判断好坏不够 |
| **关系是事后测的，不是事前造的** | 能发现"这两件在糊"，不能"设计它们交织" | 当前最大的结构差距 |

### C. 现在做不到

| 做不到 | 缺什么 |
|---|---|
| **离题** / **拼接** | 没有"离骨架多远"，也没有"接缝" |
| 渐变 / 渐次进入 | 在场是整小节开关，没有交叉淡入、没有小节内曲线 |
| 回读人类改动 | 单向生成 |
| 人声发声 | 模型有了（§3.10），词层与音源都没实现 |
| 自动生成多候选 | 方向算子还只是纸上的假设，没有生成器 |

### D. 结构性缺口

1. **骨架与编排已分离，变换已落地，fidelity 未接。** 素材轨 + 承载者 + `op:` 变换链（octave / transpose / invert / retrograde / augment / diminish / fragment / sequence，带血统追溯）已实现；无来源轨、fidelity 向量尚未实现。
2. **四层是单声部视角。** 关系层刚起头，且只能测不能造。
3. **轨迹模型假设素材可重复。** 通谱体就撞墙（《送别》被迫显式重复末句）。
4. **和声空间只有三和弦。** 四度叠置、音簇、调式混合没有语法。
5. **所有参数都是阶梯，不是曲线。** 密度、音区、力度、在场全是整小节粒度。
6. **没有骨架就没有参照物。** fidelity 全线 N/A，系统退化成生成器——只能如实告知，不能假装。
7. **闭环建好了，但没被真实使用过一次。** 建好不等于验证过：“听到 → 说出 → 改”这条链是不是真的更便宜，现在一点证据都没有。

### E. 一句话

> 现在能做的是：**把一份明确的骨架，忠实地、可验证地、秒级地铺成一个可听的编曲。**
> 现在刚建好的是：**听到 → 比较 → 指认差异** 的闭环。
> 还没有证据的是：这条闭环真的让人更容易说出“哪里不对”。

## 9. 风险

- **R1｜自造语言的陷阱。** 缓解：不造语法，只定数据形状。
- **R2｜情绪词表的空转。** 缓解：条目必须可试听验证，否则删除。
- **R3｜过度工程。** 缓解：先让内环能听。
- **R4｜工具幻觉。** 缓解：C2。
- **R5｜元层漂移。** 讨论架构的时间超过做实验。缓解：任何争论超过一天，立刻转成 spike。
- **R6｜几何的诱惑。** 把"结构自洽"误当作"作品成立"。缓解：P10。
- **R7｜测量本身的谎言。** 我们的测量代码出过一次 bug：输出漂亮、逻辑自洽、完全不报错。缓解：每个指标都要有一条小到能手算的样例。
- **R8｜服从的诱惑。** 任何形式的"根据你的历史"都可能把工具变成镜子（P15）。缓解：判断只以 pin 的形式落库。
- **R9｜变成自身理论的执行器。** 项目已有一套相当完整的思想体系，可能在真正的音乐实验之前，就先对"什么是音乐""怎么创作""什么算合理的模型"形成过多共识。最后做出的东西只能生成它自己能解释的音乐。
  缓解：允许它生成自己无法解释的东西、违反自己模型的东西；允许用实践推翻今天的空间/轨迹/关系/素材。**文档里的每一条结论都要能被打回假设。**
- **R10｜可测的东西挤掉重要的东西。** 工程上能证明的东西（可寻址、可追溯、确定性）会不断被优先解决，而"听起来有没有生命"永远排到以后。缓解：C18 的三分法；以及定期问一句"上一次因为听到某个东西而改变设计，是什么时候"。

## 11. 假设（未验证）

下列各条曾经以结论的身份写在本文里，现在降为假设。
它们不是被推翻了，是**没被验证过**——而把猜测写成结论，正是 R9 的入口。

| # | 假设 | 为什么降级 | 什么能把它升回去 |
|---|---|---|---|
| H1 | `F(t, H, A, …)` 是音乐生成的基本形式 | 时间不是上下文；自变量清单装不下“该回应谁、该不该沉默” | 证明知道这些自变量就足以生成 |
| H2 | 形式与和声是同一路径的不同尺度 | 反例就在本曲：形式来自**在场**，不来自和声 | 找到一首形式和声驱动、且该模型预测准的曲子 |
| H3 | 厚重感来自同音/八度叠置 + 低频相位一致 | n=1；相位是**混音**属性，换音源/房间就不成立 | 控制变量对比齐奏 vs 密集异音叠置 |
| H4 | 情绪词有相对稳定的参数方向 | 同参数在不同语境下可产生相反情绪 | 每条方向算子经过试听验证（§3.5） |
| H5 | “最近邻”能产生有价值的声部进行 | 实测退化成停在同一个共同音 | 找到“何时允许跳”的规则并验证 |
| H6 | 四条空间轴彼此独立 | 音区已经分裂成两种（素材音区 / 织体音区） | 证明沿一条轴移动不扰动其他轴 |
| H7 | 关系类型能有效指导生成 | 目前只会测、不会造 | 能“声明对答”并得到可听的对答（§10 Q4） |
| H8 | fidelity 能充分描述素材身份 | 身份是创作判断，不是距离计算的产物 | 永不升级：已明确由人主张、系统举证 |
| H9 | MusicXML 是最理想的出口 | 四个损失点（连音线/符杠/等音/鼓谱）未实测 | 三个导出器并排试完 |
| H10 | 所有操作都应量化到音乐边界（C9） | 与微时序、rubato、渐快直接冲突 | 证明量化不损害“人味”，或为微时序开例外 |

> 降级不需要理由，**升回去需要证据**。这是本项目对自身结论的默认态度。

## 12. 词汇表

| 词 | 含义 |
|----|------|
| **意图层 L0** | 语言、情绪、参考曲、叙事。易变、不精确、不是资产。 |
| **规格 Spec L1** | 可寻址的编曲描述（骨架 + 空间 + 政策 + 轨迹约束 + pins + seed）。唯一可编辑真源。 |
| **事件图 L2** | `(声部, 起止时间, 音高, 力度, 发音法)` 的平坦列表。构建产物。 |
| **政策 Policy** | **怎么走**：跳/邻、快/缓、延迟/即时解决。 |
| **空间 Space** | **哪些状态可达**：和声 / 节奏 / 音区 / 在场的语法。 |
| **轨迹 Trajectory** | `γ : [0,T] → Space`，具体的游历。 |
| **织物 Texture** | 每件乐器此刻做什么。唯一需要"音符字符串"的层。 |
| **outside-time / in-time** | Xenakis 之分：结构语法（≈ L1）与时间中的实现（≈ L2）。 |
| **方向算子** | 情绪词的正确形式："更密/更疏"这类只含方向的算子，不含数值。 |
| **在场空间** | 编制幂集（2ⁿ）。配器 = 在这里走的路径；空集合法。 |
| **分量表** | 每小节每声部一行实测：发声拍数、dB、音区、是否承载文本。取代单一的"显著度"分数。 |
| **关系 relation** | 两个声部的形态：对答 / 接力 / 互补 / 叠置 / 影子 / 让位 / 碰撞。 |
| **交错度 interlock** | \|A∪B\| 高而 \|A∩B\| 低 —— "交织"的可测形式。 |
| **骨架 skeleton** | "拿掉它就不再是它"的那些东西。分层：素材 / 结构 / 关系 / 感受。 |
| **素材轨 material track** | 骨架层的一条时间线：什么音乐、在哪几小节。与"谁演奏"分离。 |
| **承载者 carrier / carries** | 声部声明它演奏哪条素材轨。同度齐奏 = 多承载者；八度叠置 = 多条实例。 |
| **cell** | 源里可寻址的最小单位（通常一个乐句）。必须人声明，不自动推断。 |
| **量词** | 一点点/稍许/更多：只在有单位的轴上有意义，必须落到数值。感受词没有对应物。 |
| **tonal 位移** | 非整八度的位移 = 移调，改变音级关系。合法，但必须报出来。 |
| **pin** | 人对某一层的承诺。写在骨架层，不写在声部上。 |
| **派生 / 离题 / 外料** | 由骨架经可指认变换得到 / 素材不可追溯但感受还在 / 引自他处。 |
| **fidelity 向量** | 每小节一组分量（轮廓 / 节奏 / 词 / 音区 / 位移）。**不合并成单一分数**；只对素材与结构层成立，用途是定位。 |
| **接缝 seam** | 拼接处的人为接口（共同音 / 枢轴 / 静默 / 硬切）。 |
| **词层** | 字-音绑定 + 咬字 + 句读。唯一携带语言的那一层。 |
| **遮蔽 masking** | 其他声部同时占住有词人声的音区与节奏，字听不清。 |
| **passaggio** | 换声区。人声独有的危险音区。 |
| **舒适区 comfort** | 好听且能持久的音域。推荐值在 `instruments/`，可被座位覆盖。 |
| **lint** | 可演奏性/可听性检查：单音限制、换气、音区碰撞、平行五八度… |
| **内环 / 外环** | 改→听（≤2 秒，离线，无 GUI）/ 导出→精修→排版→分发（分钟级，人工）。 |
